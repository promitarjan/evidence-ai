Reference Guide

EvidenceAI — App Map

“Don’t just cite. Prove your claims.” — Academic evidence auditor & citation integrity engine.

Architecture & Core Loop

EvidenceAI audits draft research papers (DOCX/PDF), extracts verifiable empirical assertions via Gemini with structured JSON schemas, grounds those claims in exact source passages from uploaded PDFs (or OpenAlex scholarly search), enables interactive citation placement (APA 7, MLA 9, IEEE), and exports a verified Word document with non-destructive in-text citations and an auto-generated References bibliography.

Reference Route: 3 Key Stops

Stop 1: Document Ingestion & Spatial Parsing Backend Service

Path: backend/services/parser.py (Symbols: parse_docx_file, parse_pdf_file)

Preserves paragraph boundaries and sentence structures from Word documents while extracting page numbers and bounding coordinates from reference PDFs to ground extracted passages.

Stop 2: Structured Claim Extraction & Evidence Grounding AI & Verification

Path: backend/services/claims.py & backend/services/verifier.py

Calls Gemini Flash with Pydantic structured schemas (ClaimListResponse). Matches local PDF text chunks first to retrieve exact verbatim quotes and page numbers; if ungrounded, queries OpenAlex scholarly metadata before grading support (Strong, Partial, Contradictory, Unsupported).

Stop 3: Interactive Split-Screen Dashboard & DOCX Export Frontend & Export

Path: frontend/src/components/AuditDashboard.tsx & backend/services/docx_exporter.py

Manages citation acceptance state, changes in-canvas highlights to resolved grey, inserts inline citation markers (e.g. (Rahman, 2025)), and calls the exporter which injects citations at the run-level without corrupting font styles or paragraph headings.

To adjust OpenAlex search filters, abstract reconstruction, or timeout limits:
File: backend/services/scholarly.py
Function: search_openalex()

A Practice to Reuse

Structured Output Schemas + Deterministic Fallbacks

When building AI-powered web applications that render complex UI state (like highlight spans and audit badges), unstructured text responses will eventually fail with JSON parse errors or missing fields.

The Solution: Define strict Pydantic schemas (e.g. ClaimListResponse) with google-genai structured outputs. Pair this with a local deterministic heuristic fallback (e.g. extract_claims_fallback in claims.py) so that even during rate limits or network outages, your core application flow remains fully testable and operational.

API Configuration & Bring Your Own Key (BYOK)

Security & Zero Hardcoded Secrets

This codebase intentionally does not contain any hardcoded API keys or credentials.

  • Google Gemini API: Users bring their own API key. Set the GEMINI_API_KEY environment variable or add it to a local backend/.env file: 
    GEMINI_API_KEY=your_gemini_api_key_here
    Note: If no key is configured, EvidenceAI automatically runs in offline fallback mode using deterministic rule-based sentence heuristics.
  • OpenAlex API: Requires no API key. EvidenceAI queries OpenAlex's public polite pool out-of-the-box for external scholarly grounding.
